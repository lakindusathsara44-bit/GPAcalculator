# Open LMS — Implementation Plan

**Design:** `docs/superpowers/specs/2026-11-10-open-lms-design.md`  
**Target:** `open.lms.html`  
**Branch:** `feature/open-lms-design`  
**Implementation style:** Static HTML/CSS/JavaScript; test-first.

## Phase 1 — Repository reconnaissance

1. Inspect the current home page links and course directory; preserve the exact 15 programme names and existing navigation conventions.
2. Identify existing CSS/JS conventions and any available test setup before choosing test commands.
3. Check whether an Open LMS page or resource dataset already exists on the branch; do not overwrite existing work.
4. Record the verified module/syllabus sources available for each programme. Do not invent module titles or claim an LMS gap without evidence.

**Checkpoint:** Confirm exact file paths and whether there is an existing test runner.

## Phase 2 — Test-first data and behaviour

1. Define a small, maintainable course/module/resource data model.
2. Add tests before implementation for:
   - all 15 programme selectors are represented;
   - module names and resource URLs are not fabricated;
   - curated resources and discovery links are distinguishable;
   - priority values are limited to 1, 2, and 3;
   - course selection, text search, resource-type filtering, and priority filtering produce the expected results;
   - empty and incomplete-data states render safely.
3. Run the tests and confirm they fail for the expected missing implementation.
4. Implement the data helpers and resource catalogue to make the tests pass.
5. Use only legitimate, attributable external links. Keep YouTube discovery as search links unless a supported public API is deliberately added later.

## Phase 3 — Build the page

1. Create `open.lms.html` with a responsive dark interface matching the existing GPA Calculator.
2. Add the 15 HND programme selector.
3. Add searchable module/topic browsing and resource cards.
4. Add resource-type and Priority 1/2/3 filters, with concise explanations of the priority policy.
5. Visually distinguish curated/checked resources from discovery suggestions.
6. Show honest empty states when module/resource data has not yet been verified.
7. Add safe external-link behaviour, accessible labels, keyboard focus states, and mobile layouts.

## Phase 4 — Integrate and verify

1. Add a link to Open LMS from `index.html` without changing unrelated GPA calculator behaviour.
2. Run the automated tests and any available HTML/JS checks.
3. Manually verify all 15 programme options, search, filters, resource links, empty states, and mobile layout.
4. Review changed files and ensure no secrets, fabricated URLs, or unsupported claims were introduced.
5. Commit the implementation on this feature branch and open a pull request to `main`; do not merge it.

## Completion criteria

- All 15 programmes can be selected.
- Module/resource discovery works without a backend or build step.
- Priority filters work and the priority definitions are visible.
- Verified resources are clearly separated from discovery links.
- Unknown or unverified module lists are labelled honestly.
- The page works on GitHub Pages and on mobile.
- Tests pass; existing GPA calculator functionality is preserved.
- A PR is ready for the user to review and merge.
